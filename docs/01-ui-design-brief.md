## 1. 產品概要

### 1.1 這是什麼

一個查詢台灣交通法規的問答工具。使用者用白話問問題（「紅燈右轉會罰多少？」），系統找出相關條文，**只根據這些條文**用白話回答，並在每個論點後面標註出處。

核心價值是**答案可驗證**：使用者隨時能看到每句話依據哪一條法規。它是查詢工具，不是聊天機器人。

### 1.2 目標使用者

- **一般民眾**：想知道某個交通行為會不會被罰、罰多少、事故後要做什麼。
- **作品集的讀者（面試官、工程師）**：想看懂系統怎麼運作。設計要讓「檢索過程」可以展開來看，但預設不干擾一般使用者。

### 1.3 收錄範圍（顯示在畫面上）

| 顯示名稱（簡稱） | 正式名稱 |
|---|---|
| 道交處罰條例 | 道路交通管理處罰條例 |
| 道安規則 | 道路交通安全規則 |
| 事故處理辦法 | 道路交通事故處理辦法 |
| 強制險法 | 強制汽車責任保險法 |

資料版本日期以「資料更新：2026-10-03」這類格式顯示。

## 2. 設計原則

1. **依據就在答案旁邊**：不用離開畫面、不用捲很遠，就能看到引用的條文原文。
2. **像工具，不像聊天**：不需要聊天氣泡、頭像、打字中動畫。一次問一題，畫面以「問題 → 答案 → 依據」組織。
3. **誠實呈現不確定**：拒答和引用驗證失敗都要清楚可辨，且不能看起來像系統壞了。
4. **過程可展開**：檢索過程是給好奇的人看的，預設收合或放在次要位置。
5. **繁體中文排版優先**：行高寬鬆，條文原文要好讀；條號、金額使用等寬數字（tabular numbers）。

### 視覺調性

可信、冷靜、清楚。參考方向：政府公文的嚴謹＋現代開發者工具的俐落。避免警示意味過重的紅色主色，紅色只留給錯誤與警告。

## 3. 版面結構

### 3.1 桌面版（≥ 1024px）

```
┌──────────────────────────────────────────────────────────────┐
│ Header：產品名稱｜收錄範圍｜評估結果｜關於                    │
├───────────────────────────────┬──────────────────────────────┤
│ 主欄                           │ 側欄：依據                    │
│  QuestionInput                 │  ArticleCard × N             │
│  AnswerStream（含 CitationBadge）│  （被引用的條文在上）         │
│                                │                              │
│ ▸ 檢索過程（可收合）            │                              │
│   PipelineFlow                 │                              │
│   RetrievalPanel               │                              │
├───────────────────────────────┴──────────────────────────────┤
│ Footer：資料來源與授權標示｜免責聲明                          │
└──────────────────────────────────────────────────────────────┘
```

設計者可以調整欄位比例與位置，但要符合原則 1：答案和依據同時可見。

### 3.2 平板（768–1023px）

依據側欄可縮窄，或改為答案下方的區塊。

### 3.3 手機（< 768px）

- 答案為主；底部以分頁或抽屜切換「答案／依據／過程」。
- 點擊 CitationBadge 時直接開啟對應條文（抽屜或展開卡片）。
- 不可出現水平捲動；左右邊距 16px。

## 4. 畫面與狀態

每個畫面請提供桌面版與手機版。

### 4.1 首頁（空狀態）

- 一句話說明：例如「用白話問交通法規，每個答案都附上條文依據。」
- QuestionInput（placeholder 例：「例如：騎機車沒戴安全帽會被罰多少？」）
- 範例問題 4～6 個，可點擊直接送出：
  - 紅燈右轉會被罰多少錢？
  - 酒駕被抓到會有什麼處罰？
  - 發生小擦撞，一定要報警嗎？
  - 騎機車可以載幾個人？
  - 違規停車被拖吊要去哪裡領車？
  - 強制險可以理賠哪些項目？
- 收錄範圍與資料版本日期
- 免責聲明（見 6.1）

### 4.2 處理中（串流進行中）

- 問題固定在上方
- 檢索過程中的 PipelineFlow 節點依序亮起：改寫問題 → 檢索條文 → 相關度檢查 → 產生答案 → 驗證引用
- RetrievalPanel 逐步出現條文卡片與相似度分數
- AnswerStream 逐字出現；引用標記出現時即時變成 CitationBadge
- 有清楚的「停止」按鈕

### 4.3 回答完成

- 答案段落中嵌入 CitationBadge（例：`道交處罰條例 §53`）
- 依據側欄列出 ArticleCard；**被引用的條文**與**檢索到但未引用的條文**視覺上要可區分
- 點擊 CitationBadge → 對應 ArticleCard 捲動到可視範圍並高亮
- 答案下方顯示：資料版本、處理耗時、「重新提問」

### 4.4 拒答

當資料範圍內找不到足夠相關的條文時：

- 標題：「資料範圍內找不到相關規定」
- 說明可能原因（問題超出收錄範圍，或問法太籠統）
- 列出收錄範圍，並給 2～3 個可改問的方向
- 檢索過程仍可展開，讓人看到為什麼拒答（例如最高相似度低於門檻）
- 語氣中性，不能像錯誤訊息

### 4.5 引用驗證警告

答案中某個引用無法對應到檢索到的條文時：

- 該 CitationBadge 改為警告樣式（例如虛線框＋警示圖示）
- hover / 點擊時說明「此引用未通過驗證，請以條文原文為準」
- 答案頂部可有一行不顯眼的提示

### 4.6 錯誤

- 連線或服務錯誤：說明發生什麼事＋「重試」按鈕
- 速率限制：「提問太頻繁，請稍後再試」，可顯示倒數
- 問題過長：輸入框下方提示字數上限（200 字）

### 4.7 評估結果頁

讓讀者知道系統品質，並說明是怎麼量的。

- 頂部：評估日期、資料版本、題數
- MetricCard × 5：
  - 檢索命中率（Recall@5）
  - 排序品質（MRR）
  - 引用正確率
  - 數字正確率（答案中的金額、點數是否與條文原文一致）
  - 拒答正確率
- 每張卡片附一句白話說明這個指標代表什麼
- EvalTable：逐題列出問題、類別、是否命中、是否正確；可展開看檢索到的條文與答案
- 可依類別篩選（罰鍰金額、行為定義、事故處理、跨法規、口語問法、範圍外）

### 4.8 關於頁

- 系統做什麼、不做什麼（不提供法律意見、不含判決與函釋）
- 運作方式的簡化流程圖
- 資料來源與授權標示（見 6.2）
- GitHub 連結

## 5. 元件清單

| 元件 | 說明 | 需要的狀態 |
|---|---|---|
| QuestionInput | 輸入框＋送出 | 預設、focus、輸入中、處理中（停用）、超過字數 |
| ExampleQuestions | 範例問題 chips | 預設、hover |
| AnswerStream | 答案文字區 | 串流中（游標）、完成、已停止 |
| CitationBadge | 行內引用標記 | 預設、hover、active（對應條文高亮中）、驗證失敗 |
| ArticleCard | 條文卡片：法規簡稱＋條號、原文、異動日期、「在全國法規資料庫查看」連結 | 被引用、未被引用、高亮、收合／展開（長條文） |
| RetrievalPanel | 檢索結果列表，每筆顯示排名、法規與條號、相似度分數條、摘要 | 載入中、有結果、無結果 |
| PipelineFlow | 流程節點圖 | 每個節點：等待、進行中、完成、略過、拒答分支；顯示耗時 |
| PipelineSteps | PipelineFlow 的簡化替代版（橫向步驟進度列） | 同上 |
| RefusalNotice | 拒答說明區塊 | — |
| ErrorNotice | 錯誤說明＋重試 | 一般錯誤、速率限制 |
| MetricCard | 指標卡 | — |
| EvalTable | 評估逐題表 | 收合、展開、篩選後 |
| Disclaimer | 免責聲明 | 完整版（首頁、關於頁）、精簡版（footer） |
| DataVersionBadge | 資料版本日期 | — |

**PipelineSteps 很重要**：實作時若流程圖被砍掉，會用它替代，所以版面在兩種情況下都要成立。

## 6. 固定文案

### 6.1 免責聲明

完整版：

> 本工具僅整理並引用公開法規條文，不構成法律意見。法規可能修正，實際適用以主管機關公告及全國法規資料庫最新內容為準。

精簡版（footer）：

> 僅供參考，非法律意見。

### 6.2 資料來源與授權標示

> 法規資料來源：全國法規資料庫（https://law.moj.gov.tw/），由法務部依政府資料開放授權條款授權使用。

## 7. 設計系統

請產出：

- **顏色 token**：背景、表面、文字（主要／次要）、邊框、主色、引用高亮色、成功、警告、錯誤；亮色與暗色兩套
- **字體**：介面與條文原文可用不同字級；繁體中文字型（例如 Noto Sans TC）；數字用 tabular numbers
- **字級、間距、圓角、陰影** token
- **圖示**：線性圖示一套，風格一致

---

## 8. 無障礙

- 文字與背景對比符合 WCAG AA（亮色、暗色皆是）
- CitationBadge 與流程節點狀態不能只靠顏色區分，要有圖示或文字
- 所有互動元件可用鍵盤操作，focus 樣式清楚

---

## 9. 不在設計範圍內

- 使用者登入、歷史紀錄
- 多輪追問（一次一題）
- 上傳文件
- 行銷型 landing page

## 11. Review 檢查清單

核准前逐項確認：

- [ ] 不看說明也知道每句話的依據在哪裡
- [ ] 答案和依據在桌面版同時可見；手機版一次點擊就能看到
- [ ] 被引用與未被引用的條文可區分
- [ ] 拒答狀態不會被誤認為系統壞掉
- [ ] 引用驗證失敗的樣式清楚但不嚇人
- [ ] 免責聲明與資料來源標示清楚可見，但不搶主畫面
- [ ] 用 PipelineSteps 取代 PipelineFlow 時，版面仍成立
- [ ] 手機版沒有水平捲動
- [ ] 暗色模式對比足夠
- [ ] 評估頁的指標一般人也看得懂

核准後，把設計稿連結與關鍵畫面截圖存到 repo 的 `docs/design/`，再開始實作。
