# ADR 0004：檢索方式（純向量 vs hybrid）

狀態：已採用（Step 4）。結論以 27 題可回答題目為基礎，樣本小，見「限制」。

## 背景

使用者用白話問，法條用法律用語。向量檢索（embedding）能把意思相近的字句對在一起，但對精確用詞（「吊銷」vs「吊扣」）與數字不敏感；關鍵字檢索（BM25）相反。常見做法是兩者合併（hybrid）。spec 把 hybrid 列為 Should，要求有了純向量的 baseline 再比較。

## 選項

1. **純向量**：Voyage `voyage-4` 的 embedding，Chroma 餘弦相似度。
2. **hybrid（jieba）**：向量與 BM25 各取前 20 條，以 RRF 合併；BM25 用 jieba 斷詞。
3. **hybrid（bigram）**：同上，但 BM25 改用「相鄰兩個漢字為一詞」的斷詞，不依賴詞典。

RRF（Reciprocal Rank Fusion）：只看名次、不看分數，每份榜單給 `1/(60+名次)`，加總後排序。向量分數（0–1）與 BM25 分數（無上限）量綱不同，不能直接相加。

## 評估方法

- 32 題全部人工驗證（`verified: true`）：27 題可回答、5 題範圍外。
- 以「條」為單位判斷命中；Recall@5 = 前 5 名找到的標準答案條數 ÷ 標準答案條數；MRR 看第一個標準答案的名次倒數（取回深度 10）。
- 範圍外題目不計 Recall／MRR。
- 三種檢索使用同一份索引（489 chunk，`data_version 2026-10-05`）與同一批題目；問題的 embedding 有快取，所以重跑結果相同。
- 原始結果：`backend/eval/results/{baseline-vector,hybrid,hybrid-bigram}.json`。重現：`uv run python -m eval.run_eval --retriever {vector|hybrid|hybrid-bigram} --name ...`。

## 結果

| 檢索方式 | Recall@5 | MRR | 命中率@5 |
|---|---|---|---|
| **純向量（baseline）** | **1.000** | **0.858** | 1.000 |
| hybrid（jieba） | 0.889 | 0.740 | 0.926 |
| hybrid（bigram） | 1.000 | 0.724 | 1.000 |

各類別 MRR：

| 類別（題數） | 純向量 | hybrid jieba | hybrid bigram |
|---|---|---|---|
| 罰鍰金額（10） | 0.883 | 0.683 | 0.783 |
| 行為定義（4） | 0.583 | 0.577 | 0.508 |
| 事故處理（4） | 1.000 | 0.875 | 0.833 |
| 跨法規（4） | 1.000 | 0.833 | 0.708 |
| 口語問法（5） | 0.800 | 0.800 | 0.700 |

## 決定

**線上檢索採用純向量**，hybrid 的程式與測試保留（`HybridRetriever`、`--retriever hybrid`），但不作為預設。

理由：兩種 hybrid 的 MRR 都低於純向量；jieba 版連 Recall@5 都掉了（有 3 題的標準答案掉出前 5 名）。在這份評估集上，加入關鍵字檢索沒有帶來好處，只讓排名變吵。

## 為什麼 hybrid 沒有贏（觀察，非定論）

- **jieba 的預設詞典不適合法律文字。** 它把「罰鍰」切成「罰」「鍰」，把「闖紅燈者」切成「闖紅」「燈者」。口語問題也會切錯（「聽到救護車鳴笛」→「救護／車鳴／笛」）。查詢與文件切法對不上，關鍵字就比不到。有測試記錄這個現象（`test_jieba_default_dictionary_splits_legal_terms`）。
- **bigram 不會切錯，但很吵。** 「罰鍰」「駕駛人」這類在幾乎每條條文都出現的詞，產生大量低鑑別力的比對，把不相關的條文推到前面。
- **RRF 對兩份榜單一視同仁。** 向量榜單已經很準時，BM25 榜單的雜訊會把正確答案往下拉。
- **這份題目對向量檢索偏容易**：Recall@5 已經是滿分，沒有往上的空間，hybrid 只能在排名上扣分。

## 限制（為什麼不要過度解讀）

- **只有 27 題可回答**，一題的名次變動就會讓 MRR 動好幾個百分點。差異顯著（0.858 vs 0.74）但不是精確值。
- **題目是 Claude Code 讀條文後擬的**，再由人工驗證。擬題者讀過條文，措辭可能比真實使用者更接近條文，這會對向量與關鍵字都偏有利，且 Recall@5 的滿分可能高估真實表現。
- **沒有調 hybrid 的參數**（RRF 常數 60、各取 20 條、BM25 的 k1／b、兩份榜單等權）。調過之後可能改善，但用同一批 27 題調參再報告會過度擬合，所以沒有做。
- **詞典**：用法律詞典（如把「罰鍰」「駕駛執照」加入 jieba）可能讓 jieba 版改善；沒有做，因為自訂詞若是參考評估題目挑的，等於洩題。若要做，應從條文本身建詞表。

## 後果

- 純向量的分數是餘弦相似度，可直接用來訂拒答門檻（Step 5）。hybrid 的 RRF 分數不能當門檻，所以 `HybridRetriever` 的結果另外保留 `vector_score`。
- baseline 數字：**Recall@5 = 1.000、MRR = 0.858**（32 題中 27 題可回答）。之後改動 chunking、檢索參數、embedding 模型，都要重跑並與此比較。
- 範圍外題目的最高相似度為 0.261–0.400，可回答題的最高相似度為 0.416–0.735。兩者目前沒有重疊，但間隙只有 0.016（0.3997 與 0.4162），且範圍外題目只有 5 題；訂拒答門檻時需要更多範圍外題目，見 Step 5。
