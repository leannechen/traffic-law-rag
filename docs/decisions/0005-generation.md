# ADR 0005：生成、引用與拒答

狀態：已採用（Step 5）。數字以 40 題評估集（27 題可回答、13 題範圍外）、單次執行為基礎，見「限制」。

## 背景

系統要「只根據條文回答，並標註出處」。生成階段的風險是：模型補充條文沒寫的內容、引用錯誤或捏造的條文、改寫或自行計算數字、對範圍外問題硬答。需要同時用提示與驗證兩層來防，並用指標量測。

## 決定

| 項目 | 決定 | 放棄了什麼 |
|---|---|---|
| 模型 | `claude-sonnet-5-5`，品質不足再換 `claude-opus-5-5`（改 `.env` 的 `LLM_MODEL`） | 一開始就用最貴的模型。換模型後可用同一份評估集比較 |
| 給模型的內容 | **整條條文**（把依項切成多塊的條文串回去），前 5 條 | 只給檢索到的那一塊。見下方「修正前後」 |
| 引用格式 | 文字標記 `[[id]]`，id 是**條**（`K0040012:35`），解析並驗證 | Anthropic API 原生的 Citations：需要把條文包成文件格式、且不能與結構化輸出並用；文字標記讓串流中可以邊輸出邊解析（Step 6），並套用我們自己的驗證規則 |
| 拒答 | 兩層：相似度門檻 0.40（第一道粗篩）＋模型輸出 `[[REFUSE]]` | 只用門檻（ADR 0004：貼近主題的範圍外問題分數與可回答題重疊） |
| 門檻 | 0.40，看**原始問題**的第一名餘弦相似度 | 看改寫後的查詢：改寫可能把範圍外問題拉高 |
| 問題改寫 | **預設關閉**（`REWRITE_ENABLED=false`），程式保留 | 預設啟用。見下方比較 |
| 數字驗證 | 從答案抽出「數字＋單位」，中文與阿拉伯數字正規化後，必須出現在**它引用的條文**；序數（「第一次」）不算數量 | 要求完全字串相同：會把「一千八百元」與「1,800 元」誤判成不同 |
| LLM 回應快取 | 評估時存在 `data/cache/`，鍵為模型＋參數＋prompt 的雜湊 | 每次重呼叫：花錢、結果不可重現 |
| 取樣參數 | 不設 temperature 等（Sonnet 5.5 不接受非預設值） | 無法用「溫度 0」求穩定，所以結果有隨機性，見限制 |

## 指標定義

- **引用正確率**：有作答、且至少引用一條標準答案（以「條」比對）的題數 ÷ 可回答題數；被誤拒的題目算錯。
- **引用精確率**（補充）：答案引用的條文中屬於標準答案的比例。引用正確率寬鬆（多引用別條不扣分），所以另列此項；偏低未必是錯，額外引用的條文可能也相關。
- **數字正確率**：答案中的數量能在「它引用的條文」找到的比例（微平均）。另列「答案數字全對的比例」與「重點金額涵蓋率」（`expected_facts` 的數量有多少出現在答案）。
- **拒答正確率**：（範圍外題有拒答＋可回答題有作答）÷ 全部題數；並分開回報範圍外拒答數、誤拒數與擋下的層級。

### 修正前後：為什麼要給整條條文

第一輪評估只給模型「每條檢索到的最高分那一塊」。人工讀完整答案後發現 q31（酒駕肇事）答得不完整：第 35 條被切成兩塊，模型只拿到後半塊，於是回答「條文中沒有酒駕本身的罰鍰金額」。這是設計缺陷，不是模型問題。改成給整條後，重點金額涵蓋率從 0.894 升到 0.985。

同一次檢查也發現，答案裡的「第一次違反」被當成數量（`1次`），誤判成數字對不上。序數不是數量，已修正，數字正確率因此 0.993 → 1.000。**這個提升有一部分是修正檢查規則，不是模型變好**，兩個原因都存在。

### 為什麼改寫預設關閉

改寫（原始問題＋最多 3 個改寫，以 RRF 合併）的結果是混合的：

- 變好：q11（2→1）、q12（3→1）、q21（2→1）、q22（2→1）。
- 變差：q10（2→4）、q14（1→2）、q24（1→5）、q32 的 Recall 從 1.0 降到 0.5（兩條標準答案只找到一條）。
- 整體 MRR 0.858→0.881，Recall@5 1.000→0.982：差異都在一兩題的範圍，不能說有贏。
- 成本：多 35 次 LLM 呼叫（約多 27% token，每題多一次往返延遲）。
- 生成階段的所有指標完全相同。
- 改寫偶爾違反「不要加入條號」：例如 q35 的查詢被加上「民法第 195 條」。

依先前的原則（和 hybrid 相同）：有贏才啟用，所以預設關閉。要重新評估可用 `--rewrite`。

## 限制（為什麼不要過度解讀）

- **評估集太容易**：生成階段的引用正確率、數字正確率、誤拒率全都是滿分，沒有區分力。與 ADR 0004 相同的原因：題目是讀過條文的人擬的，措辭貼近條文。滿分不代表真實使用者的問題都能答對。
- **單次執行**：模型不能設溫度，結果有隨機性。快取讓重跑結果相同，但不代表穩定；沒有多次執行的變異數。
- **引用精確率 0.646**：模型常額外引用其他條文（例如 53-1、21-1、40、74）。其中有些是相關的補充，有些較牽強（例如 q22 引用慢車的第 74 條、第 129 條），需要人工讀答案判斷，指標無法區分。
- **q40 的標籤有疑義**：「汽車多久要保養一次？」被標為範圍外，但道安規則第 39-3 條寫「汽車所有人除依規定接受車輛檢驗外，應依原廠規定時間自行實施保養及檢查」。模型據此回答並說明「條文沒有規定具體間隔」，是忠實的回答。這題算「範圍外卻作答」是標籤問題，不是模型問題；範圍外拒答 12/13 因此可能低估。標籤由人工決定，尚待處理。
- **重點金額涵蓋率仍有缺口**：q04 漏了機車的一千二百元，因為題目問的是「開車」，模型沒提機車是合理的。標準答案的 `expected_facts` 把它列進去是題目設計的問題。
- **數字檢查的範圍**：能抓「答案的數字不在引用條文」，抓不到「引用對了、但數字取自無關段落」或「引用編號合法但不支持該論點」。這需要人工讀答案。
- **兩層拒答對貼近主題的問題有效，但樣本小**：13 題範圍外中，6 題被門檻擋下、6 題被模型擋下、1 題（q40，見上）作答。「公車專用道可以走嗎」通過了門檻（0.547），由模型拒答。
- **安全機制 fallback** 已開啟但未在評估中被觸發，行為未驗證。
- 本次只用 Sonnet 5.5，沒有與 Opus 5.5 比較。

## 後果

- Step 6 串流時，答案中的引用 id 是**條**，不是切塊；解析 `[[…]]` 要處理標記被切在兩個 delta 之間的情況。
- `/api/chunks/{id}` 的 `article_text` 可重用 `ChromaArticleSource`。
- 之後任何改動 prompt、門檻、chunking、模型或檢索，都要重跑 `run_generation_eval` 並與上表比較。
