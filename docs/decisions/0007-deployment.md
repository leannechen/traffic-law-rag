# ADR 0007：部署

狀態：已採用（Step 12）。映像已在本機建置並跑通；Fly.io 上線需要自己的 Fly 帳號，實測冷啟動與月成本見 README。

## 背景

要有一個公開 URL。限制：個人專案、流量很低、不想為閒置付費；線上需要兩把金鑰（Anthropic、Voyage）和 6 MB 的向量索引。

## 決定

| 項目 | 決定 | 放棄了什麼 |
|---|---|---|
| 形態 | **單一映像、單一 URL**：後端（FastAPI）一併提供前端建置檔（`STATIC_DIR`），`/api/*` 之外的路徑回 `index.html` 給 React Router | 前後端分開部署（靜態託管＋API）：要設 CORS，而且 SSE 要跨網域；本專案前端沒有 SSR 或 CDN 需求，單一映像少一個服務、少一類設定錯誤 |
| 索引 | **索引當作 artifact 放進映像**（`COPY data/index`）。索引由本機 `build_index` 產生，不進 git，部署時才進映像 | 在映像建置時重建：建置要帶 Voyage 金鑰、每次部署花 API 費用，且結果可能與評估時的索引不同；把索引 commit 進 git：二進位檔每次重建都增加 repo 大小 |
| 主機 | Fly.io，`shared-cpu-1x`／512 MB，`auto_stop_machines` 沒流量時停機 | 常駐機器：每月固定費用但無冷啟動。流量低，選擇省錢並接受冷啟動 |
| 金鑰 | `fly secrets set`，不寫進映像與 `fly.toml` | |
| 速率限制 | 映像內 `TRUST_PROXY=true`（Fly 代理會帶 `X-Forwarded-For`，只取最後一個值）；仍是單實例、記憶體內計數，所以**只跑一台機器** | 多實例：計數不共享，限制會失效（見 ADR 0006） |
| CORS | 同源不需要；`CORS_ORIGINS=[]` | |
| 評估頁資料 | `backend/eval/results/latest.json` 一併複製進映像（config 的 `REPO_ROOT` 靠映像內目錄結構與 repo 相同：`/app/backend`、`/app/data`） | 執行時重跑評估：要花 API 費用 |

## 防止 API 額度被濫用

站上用的是我自己的 Anthropic 與 Voyage 金鑰。每次提問約 US$0.012；只靠「每 IP 每分鐘 10 次」，單一 IP 一天理論上可燒約 US$170，換 IP 更沒上限。所以分三層，由內到外：

| 層 | 做法 | 擋得住 | 擋不住 |
|---|---|---|---|
| 1. 供應商端花費上限 | 專用 API key（可單獨撤銷），Anthropic 與 Voyage 都設每月 US$10 上限 | 一切，包含程式有漏洞或被攻擊 | — （這是底線） |
| 2. 應用程式全站每日上限 | `DAILY_ASK_LIMIT`（預設 300 次／UTC 日）；超過回 503，`detail: "daily_limit"`，前端顯示「今天的提問額度用完了」。`max_tokens` 8000 → 2000（實測最多輸出約 650） | 一般濫用；最壞每天約 US$3.6 | 計數在記憶體，機器重啟（含停機後喚醒）就歸零，所以有意的攻擊可以靠重啟繞過 |
| 3. 每 IP 速率限制（既有） | 每分鐘 10 次、問題 200 字 | 單一來源的連發 | 多個 IP |

放棄了：**存取門檻**（通關密碼、Cloudflare Turnstile）。能擋掉大部分機器人，但讀者點開連結就要能用，門檻會傷害展示；驗證碼還要多一個外部服務與前端改動。暫不做，若要在公開場合貼連結再考慮帶 token 的連結。

也放棄了**限制同時進行的串流數**：計數要在串流結束時釋放，但使用者在串流開始前斷線時事件產生器可能根本不會執行，容易漏釋放而把額度鎖死；有上面三層已足夠。

每日額度只在通過速率限制後才扣，被 429 擋下的請求不扣；被門檻擋下、沒呼叫模型的問題仍會扣（保守，且實作單純）。

## 後果

- 更新資料的流程是手動、每月一次：重跑 ingestion → `build_index` → `run_generation_eval --publish`（若要更新評估頁）→ `fly deploy`。索引與評估結果因此永遠跟著映像一起版本化。
- 部署當時必須在**有 `data/index/` 的機器上**做（本機）；CI 不部署，也因此不能在 CI 建這個映像。**後來由 [ADR 0008](0008-continuous-deployment.md) 補上 CD**：索引放 GitHub Release，push 到 main 後自動部署。
- 冷啟動 ＝ 機器啟動 ＋ 第一次請求載入索引與建立客戶端。機器停機時第一個使用者會等比較久。
- 單一機器、單一區域：沒有備援。低流量的個人專案可以接受。
