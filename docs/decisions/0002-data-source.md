# ADR 0002：資料來源

狀態：已採用（Step 2）

## 背景

系統需要交通法規的條文原文。資料來源會直接決定法律風險（授權）、維運成本（格式穩定度）與引用品質（條文是否完整、有無廢止版本）。

## 選項

1. **爬 `law.moj.gov.tw` 網頁**（如 `LawAll.aspx?pcode=...`）
2. **政府資料開放平臺的全國法規資料庫打包檔**（data.gov.tw 18289 法律、18290 命令）
3. 人工從網站下載單一法規檔

## 決定

採用選項 2：每月更新的 XML ZIP，授權為「政府資料開放授權條款－第 1 版」。ingestion 只取 `targets.yaml` 列出的 pcode，其餘法規在串流解析時即丟棄，不寫入 `data/processed/`、不進索引。

## 為什麼不爬網頁

- 該網站的 robots.txt 禁止自動化存取，爬取在授權上站不住腳。
- HTML 結構會隨改版變動，爬蟲是脆弱的相依。
- 開放資料有結構化欄位（條號、章節、廢止註記、異動日期），不需要從 HTML 反推。

## 放棄了什麼

- **附件內容**：開放資料的附件只有檔名與下載網址，沒有內容。最明顯的損失是《統一裁罰基準》的附表（各違規行為的罰款表）。系統因此不能把這份表當金額來源（見 `docs/data-format.md`）。
- **即時性**：資料每月更新一次，法規剛修正時索引會落後最多一個月。UI 以 `data_version` 標示資料日期。
- **檔案體積**：全部法規打包在一起（命令檔解壓後 112 MB），即使只要 5 部也得整包下載。以串流解析處理，記憶體用量小，快取後同一份資料只下載一次。

## 後果

- 以 pcode 識別法規，不用名稱（名稱可能帶後綴，且同名法規可能有廢止舊版，例如道路交通事故處理辦法的 `K0040015` 與現行 `D0080090`）。
- 目標清單若指到已廢止或不存在的法規，解析會報錯，避免默默少一部法規。
- 若日後要涵蓋附表內容，需要人工下載並另行處理，不得寫爬蟲。
